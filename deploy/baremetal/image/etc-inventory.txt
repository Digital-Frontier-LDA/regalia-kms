# /etc and /var on a verity-/usr host: what is this host's own, where it lives, and what is the image's (#61, the
# dm-verity design of 2026-10-05, comments 17-20; bead K61V-5, regalia-kms-r1s.4).
#
# THE LAYOUT: / is a tmpfs, so /etc starts EMPTY at every boot; /usr is the read-only erofs image under dm-verity and
# holds the image's /etc as /usr/share/factory/etc (build-rootfs.sh); /var is this host's LUKS2 volume and the ONLY
# thing that survives a reboot. units/00-regalia-etc.tmpfiles.conf makes /etc from the factory copy (C+) and links each
# per-host /etc path to its /var name (L), from regalia-etc-factory.service, BEFORE systemd-sysusers.
#
# FOUND BY SEARCHING, not from memory: tests/test_baremetal_etc_inventory.py refuses an /etc path named in deploy/'s
# code or units that no row here covers, and holds [per-host] equal to deploy/baremetal/hostpaths.py and to the
# tmpfiles links. tests/test_baremetal_etc_writes.py refuses a WRITE to a [per-host] path by its /etc name.
# MEASURED, where a row says so: e2e/etc-factory.sh on a Debian 13 host tree (the image's [packages], the commit's
# units, sysusers and tmpfiles, the factory copy as build-rootfs.sh makes it), with the image's own systemd 257.
#
# Format: one row per line, fields separated by " | ", in sections; blank lines and lines starting with # are ignored.

[boot]
# /etc path | how it is made at boot | why not from the factory copy, nor on /var
/etc/machine-id | PID 1 writes it before any unit: from /var/lib/dbus/machine-id when /etc has none (machine-id(5), systemd 257), else a new random ID at the first boot; 00-regalia-etc.conf's `C /var/lib/dbus/machine-id - - - - /etc/machine-id` keeps that one on /var (overriding dbus.conf's link back to /etc); the factory copy's empty file never replaces it (C+, e2e/etc-factory.sh) | not a link to /var: PID 1 reads it before any tmpfiles pass. Not systemd.machine_id= on the command line: that is the signed UKI's, the same on every host and measured into PCR 11. /var is mounted by the initrd (the UKI's systemd.mount-extra=, K61V-4), and OnQemuVerity holds the ID equal to /var's, boot after boot
/etc/ld.so.cache | the factory copy; ldconfig.service (ConditionNeedsUpdate=/etc) rewrites it at every boot, /etc/.updated never surviving | derived from /usr; the same bytes every boot
/etc/mtab | systemd's own tmpfiles (etc.conf: L+ ../proc/self/mounts), and the factory copy's identical link | derived

[image]
# /etc path | why it is the image's (identical on every host, in /usr/share/factory/etc), not this host's
/etc/passwd | the image's system users, allocated at build by systemd-sysusers and the packages' maintainer scripts; copied before systemd-sysusers runs at boot so the UIDs/GIDs the files on /var carry survive (e2e/etc-factory.sh)
/etc/group | as /etc/passwd
/etc/shadow | as /etc/passwd (no password is set: every account is locked or nologin)
/etc/gshadow | as /etc/passwd
/etc/nsswitch.conf | the package default; regalia-authtime and regalia-boot-session bind it read-only
/etc/ld.so.conf | the package default; elfclosure.py reads it on the build tree
/etc/apparmor.d | the daemon's profile (build-rootfs.sh installs usr.sbin.regalia-kms) and the packages' profiles; loaded by apparmor.service AFTER the factory copy (units/apparmor.service.d/regalia-etc.conf)
/etc/polkit-1/rules.d | 50-regalia-kms-pcscd.rules is the same on every host: it belongs in the image (today README.md has the operator install it; not yet in build-rootfs.sh: [open]); os_probe reads it
/etc/crypttab | the image's own (Debian's, empty); the volume is opened by the INITRD's crypttab (90regalia-unlock: PARTLABEL=regalia-root, nothing per host); host_probe reads /etc/crypttab and must read the initrd's: K61V-3/-4's
/etc/initrd-release | only in the initrd; regalia-boot-session's ConditionPathExists=! tells the two apart
/etc/systemd/tpm2-pcr-signature.json | never written: systemd-stub puts the UKI's into /run/systemd; signkey and seal-hsm-pin.sh read the first of /run, /etc, /usr
/etc/systemd/system/regalia-sync.service | not written on a node: owner.py's NODE_MARKS refuses to run where the unit exists, the image's is /usr/lib/systemd/system
/etc/systemd | the packages' defaults (journald.conf, system.conf, logind.conf, ...): the image's
/etc/chrony | Debian's chrony.conf (a package conffile, never touched) and sources.d; only regalia.conf in it is this host's ([per-host])
/etc/ssh | the directory; only the ed25519 host key in it is this host's ([per-host])
/etc/default | the packages' defaults; only prometheus-node-exporter in it is this host's ([per-host])
/etc/nftables.d | made by the link's parent
/etc/nftables.conf | the image's (build-rootfs.sh, regalia-kms-r1s.8): `flush ruleset` and an include of this host's ruleset, /etc/nftables.d/regalia-kms.nft, by name; Debian's accept-everything example table is not kept
/etc/hostname | build-rootfs.sh writes a fixed one before the factory copy: `localhost` (MEASURED before, K61V-5 #723: the BUILD host's, copied in by mmdebstrap). Not per host: PID 1 sets the hostname before the copy ([early]) and nothing reads it; a node is named by node.json. e2e/etc-factory.sh fails if it is the builder's (regalia-kms-r1s.6)
/etc/hosts | as /etc/hostname: the loopback names only, fixed (it was the builder's); a name the host must resolve is in DNS (/etc/resolv.conf, [per-host])
/etc/fstab | build-rootfs.sh writes comments only (it was mmdebstrap's placeholder): / is a tmpfs, /usr and /var come from the kernel command line and the initrd ([early])
/etc/apt/sources.list.d | emptied by the build: a host is updated by a new image, never by apt

[early]
# /etc path | read by | before the factory copy, so on its compiled-in default: why that is acceptable, or [open]
/etc/systemd/system.conf | PID 1, at start | Debian's file sets nothing (every line commented): the defaults are the same
/etc/systemd/system | PID 1, loading units | EMPTY when units load, and nothing is enabled there: the image's enablement is under /usr/lib/systemd/system/*.wants (K61V-4: deploy/baremetal/image/units-enabled.txt names each link, or the build stops), and a `disable *` preset (00-regalia-kms.preset) makes a first boot's preset-all pass, which runs at every boot, enable nothing. What a host starts once ITS state is there (the firewall, the node units, the audit shippers) is enabled there too, each gated on its per-host file under /etc (on /var), and per-host unit content comes from /var through the image's generator (regalia-kms-r1s.8: units-enabled.txt [per-host]); tests/etc_writes.py refuses a write under /etc/systemd/system in deploy/
/etc/systemd/journald.conf | systemd-journald (started before sysinit) | Debian's file sets nothing; journald reads it again on a restart
/etc/udev/udev.conf | systemd-udevd | Debian's file sets nothing
/etc/modules-load.d/modules.conf | systemd-modules-load (sysinit, not ordered after the copy) | empty in the image; the image's modules belong in /usr/lib/modules-load.d
/etc/sysctl.d | systemd-sysctl | only Debian's README in the image; the image's settings belong in /usr/lib/sysctl.d
/etc/fstab | systemd-fstab-generator (before any unit) | the image's is the build's empty placeholder; mounts come from the initrd and the kernel command line (K61V-3/-4)
/etc/crypttab | systemd-cryptsetup-generator | none in the image; the volume is opened in the initrd
/etc/hostname, /etc/hosts | PID 1 (the hostname), nss | the hostname is set by PID 1 from /etc/hostname before the copy: it stays the kernel's default (or the command line's systemd.hostname=); nothing in deploy/ reads it
/etc/machine-id | PID 1 | [boot]
/etc/locale.conf, /etc/vconsole.conf, /etc/localtime | PID 1, systemd-vconsole-setup | the defaults (C.UTF-8, UTC, the kernel's keymap): the image's are the same
