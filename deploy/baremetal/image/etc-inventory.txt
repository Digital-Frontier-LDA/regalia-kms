# /etc and /var on a verity-/usr host: what is this host's own, where it lives, and what is the image's (#61, the
# dm-verity design of 2026-10-05, comments 17-20; bead K61V-5, regalia-kms-r1s.4).
#
# THE LAYOUT: / is a tmpfs, so /etc starts EMPTY at every boot; /usr is the read-only erofs image under dm-verity and
# holds the image's /etc as /usr/share/factory/etc (build-rootfs.sh); /var is this host's LUKS2 volume and the ONLY
# thing that survives a reboot. units/00-regalia-etc.tmpfiles.conf makes /etc from the factory copy (C+) and links each
# per-host /etc path to its /var name (L), from regalia-etc-factory.service, BEFORE systemd-sysusers.
#
# FOUND BY SEARCHING, not from memory: tests/test_baremetal_etc_inventory.py refuses an /etc path named in deploy/'s
# code or units that no row here covers, and holds [per-host] equal to deploy/baremetal/hostpaths.py and to the
# tmpfiles links. tests/test_baremetal_etc_writes.py refuses a WRITE to a [per-host] path by its /etc name.
# MEASURED, where a row says so: e2e/etc-factory.sh on a Debian 13 host tree (the image's [packages], the commit's
# units, sysusers and tmpfiles, the factory copy as build-rootfs.sh makes it), with the image's own systemd 257.
#
# Format: one row per line, fields separated by " | ", in sections; blank lines and lines starting with # are ignored.

[boot]
# /etc path | how it is made at boot | why not from the factory copy, nor on /var
/etc/machine-id | PID 1 writes it before any unit: from /var/lib/dbus/machine-id when /etc has none (machine-id(5), systemd 257), else a new random ID at the first boot; 00-regalia-etc.conf's `C /var/lib/dbus/machine-id - - - - /etc/machine-id` keeps that one on /var (overriding dbus.conf's link back to /etc); the factory copy's empty file never replaces it (C+, e2e/etc-factory.sh) | not a link to /var: PID 1 reads it before any tmpfiles pass. Not systemd.machine_id= on the command line: that is the signed UKI's, the same on every host and measured into PCR 11. Needs /var mounted before PID 1 (by the initrd, K61V-3/-4's): [open] if it is not
/etc/ld.so.cache | the factory copy; ldconfig.service (ConditionNeedsUpdate=/etc) rewrites it at every boot, /etc/.updated never surviving | derived from /usr; the same bytes every boot
/etc/mtab | systemd's own tmpfiles (etc.conf: L+ ../proc/self/mounts), and the factory copy's identical link | derived

/etc/systemd | the packages' defaults (journald.conf, system.conf, logind.conf, ...): the image's
/etc/chrony | Debian's chrony.conf (a package conffile, never touched) and sources.d; only regalia.conf in it is this host's ([per-host])
/etc/ssh | the directory; only the ed25519 host key in it is this host's ([per-host])
/etc/default | the packages' defaults; only prometheus-node-exporter in it is this host's ([per-host])
/etc/nftables.d | made by the link's parent; nftables.conf's include of it is [open]
/etc/hostname | MEASURED: the image's is the BUILD container's hostname (13 bytes, leaked by mmdebstrap), and so are /etc/hosts, /etc/resolv.conf and /etc/fstab: the build must write fixed ones (build-rootfs.sh, [open]); nothing reads the hostname
/etc/apt/sources.list.d | emptied by the build: a host is updated by a new image, never by apt

/etc/systemd/system | PID 1, loading units | EMPTY when units load: every enablement the image made there (measured: apparmor.service and systemd-pstore in sysinit.target.wants, chrony, prometheus-node-exporter and remote-fs.target in multi-user.target.wants, pcscd.socket, getty@tty1, the apt/dpkg/fstrim timers, the chronyd.service alias) is not seen: [open]

/var/lib/dpkg | dpkg's database: status, the packages' file lists, maintainer scripts (7.7 MB) | [open]: the owner's (see [open])
/var/cache/debconf | debconf's answers (1.7 MB) | with /var/lib/dpkg ([open]); nothing at run time reads it
/var/lib/ucf, /var/lib/apt | the conffile hashes, apt's extended_states and periodic stamps | with /var/lib/dpkg ([open]); a host is never updated by apt

/var/cache/apparmor | apparmor_parser's compiled profiles (empty in the image) | emptied at every boot (00-regalia-etc.conf: D): a cache newer than the profile is loaded, and the image's profiles carry the build's clamped mtime, so another image's cache would win
/var/lib/dbus/machine-id | dbus's link to /etc/machine-id (dbus.conf) | the machine ID itself, kept by 00-regalia-etc.conf ([boot])
/var/cache/ldconfig | ldconfig's aux cache | made again at boot (ldconfig.service); not needed from the image
/var/log | the packages' log directories (journal, prometheus, runit/pcscd), btmp, wtmp, lastlog | made by the packages' and systemd's tmpfiles at boot (measured: journal, private; d /var/log); a log written at build is not the host's
/var/lib/prometheus/node-exporter, /var/lib/chrony, /var/lib/tpm2-tss, /var/lib/pam, /var/lib/regalia-* | the daemons' state directories | made at boot by the packages' and regalia's tmpfiles.d (measured d lines) or StateDirectory=; the host's own state, on its LUKS2 volume
/var/lib/xml-core, /var/lib/sgml-base, /var/lib/python, /var/lib/shells.state, /var/spool/mail, /var/backups | the packages' registries and empty directories | nothing at run time reads them: dropped with /var/lib/dpkg's move ([open])

[open]
# subject | the question | recommendation (who decides)
/var/lib/dpkg | The image's package database is on /var, which is per host and outside the verity hash, so a host's /var would disagree with its /usr after an A/B update. Options: A) move it into /usr (/usr/lib/sysimage/dpkg, what the hermetic-/usr distributions do) with a link from /var/lib/dpkg, and drop debconf/ucf/apt state; B) leave it out of the image (delete at build) and keep the package list as packages.txt and the SBOM; C) keep it on /var as built, accepting the drift. | A: the image says what it contains, read-only and measured, and dpkg -l still works. The OWNER's (asked as q-18); K61V-4 builds it
/etc/systemd/system enablement | PID 1 loads units while /etc is empty, so every unit the build enabled under /etc/systemd/system is not started, apparmor.service among them (only regalia-etc-factory's drop-ins pull it in by ordering, not by Wants) | move enablement into /usr: /usr/lib/systemd/system/*.wants links or a preset file at build (build-rootfs.sh, slice 2's file: K61V-4); the QEMU boot test must show regalia-kms.service, apparmor and chrony started
ConditionFirstBoot | /etc/machine-id is missing when PID 1 starts, so every boot counts as the first: systemd-firstboot.service (--prompt-*) and preset-all run each time | K61V-4's QEMU boot must show they do not prompt (the factory /etc sets locale, keymap, timezone, root) or mask systemd-firstboot.service in the image
/var mounted before PID 1 | the machine ID kept on /var is read by PID 1 only if the initrd mounted /var | K61V-3/-4's initrd mounts /var (PARTLABEL regalia-root) before switch-root
per-host systemd drop-ins | README.md and SSH.md have the operator write /etc/systemd/system/*.d drop-ins (credentials, hardening, firewall); on a tmpfs /etc they are gone at reboot and unseen at unit load | the image's, under /usr/lib/systemd/system, with any per-host value read from /etc/regalia (on /var)
nftables | /etc/nftables.conf (the image's) must include /etc/nftables.d/*.nft and nftables.service be enabled in /usr | the image (K61V-4)
polkit rule | 50-regalia-kms-pcscd.rules is installed by the operator into /etc/polkit-1/rules.d | install it into /usr/share/polkit-1/rules.d at build (K61V-4)
build leftovers in the factory copy | /etc/hostname, /etc/hosts, /etc/resolv.conf and /etc/fstab are the BUILD container's (measured: a 12-character container hostname, "Generated by Docker Engine"), with .pwd.lock and the passwd-/group-/shadow-/gshadow- backups | build-rootfs.sh writes fixed ones and deletes the rest before the factory copy (K61V-4); reproducibility shows it if the build host changes
chronyd's AppArmor profile | chronyd reads /etc/chrony/regalia.conf through the link, and AppArmor checks the /var file | shipped: the local include (apparmor/local/usr.sbin.chronyd) linked by 00-regalia-etc.conf; K61V-4's boot shows chronyd starts in enforce mode
