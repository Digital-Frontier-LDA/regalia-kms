# What the KMS host image STARTS, enabled under /usr (#61 K61V-4, bead regalia-kms-r1s.3), and what the packages enabled
# that it does not. build-rootfs.sh reads this file.
#
# WHY UNDER /usr: / is a tmpfs, so /etc is EMPTY when PID 1 loads its units (the factory copy comes later, from
# regalia-etc-factory.service), and an enablement under /etc/systemd/system is never seen (etc-inventory.txt, [early]).
# So the build makes each [enabled] line a link in /usr/lib/systemd/system/<target>.wants/ (an [alias] a link beside its
# unit), REFUSES a link a package made under /etc/systemd/system that no line here names, and then removes every one
# of those from the image's /etc: what the image starts is this file, and the factory copy holds no enablement.
#
# FIRST BOOT, EVERY BOOT: /etc/machine-id is missing when PID 1 starts, so every boot is a "first boot" (machine-id(5)),
# and PID 1 then applies the preset policy to /etc/systemd/system before it loads units (systemctl preset-all, enable
# only). Debian ships no "disable *" preset, so that would enable every unit with an [Install] section on every boot.
# The image's preset (regalia-kms.preset, installed as /usr/lib/systemd/system-preset/00-regalia-kms.preset, read
# before any other) is "disable *": the preset pass enables nothing, and this file stays the whole of it. The units
# with ConditionFirstBoot= in the image are the timers dropped below (measured: Debian 13, these packages); trixie's
# systemd has no systemd-firstboot. The QEMU boot shows /etc/systemd/system empty after boot (e2e/unlock-boot-qemu.sh).
#
# PER HOST (regalia-kms-r1s.8): what a host starts once ITS state is there (the firewall, the node's units, the audit
# shippers) is enabled here too, in [per-host], each gated on its per-host file; what the image never runs is [masked].
# Nothing an operator does writes /etc/systemd/system (tests/etc_writes.py refuses it in deploy/).
#
# Format: one entry per line, fields separated by " | ", in sections. Blank lines and lines starting with # are ignored.

[enabled]
# target | unit | why the host starts it
sysinit.target | apparmor.service | loads the profiles from /etc/apparmor.d (the factory copy first: units/apparmor.service.d), the daemon's among them; regalia-kms.service requires it (units/regalia-kms.service.d/apparmor.conf)

# never seen at unit load. Each line is enabled here, under /usr, like [enabled], and GATED: the unit (or a drop-in of
